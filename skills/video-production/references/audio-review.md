# Qwen-Omni 音频复核

口播需要判断领读、非正式发言、吞字和换气截断时读取本页。`audio-review`把真实音频交给`qwen3.8-omni-flash`，程序批量收集报告；DeepSeek读取汇总及异常，不为每个切口发一次模型请求。它是音频模型复核，独立于ASR转写、波形同步和人工听审。仅凭声音不能断言谁在画面里，身份仍需结合原片画面；疑点回源可将原声与真实时码抽帧一起送入同一模型。

## 三个时机，共用一个预算

沿用主Skill环境门和业务空间`.env`，本入口固定北京地域价格，单项目同一原片的听审总预算为 **0.2元**，包括原片、成片不同revision及未确认请求的费用预留。API费用不包括ASR、DeepSeek主会话或本地渲染。先省略`--execute`预检；用户要求音频听审即授权在该预算内执行，无需逐切口询问。

1. **选段前**检查原片声音，识别领读与正式讲述的交替、试词和拍摄交流。报告的疑点是候选，按上下文和画面核对后写入现有`spans/excluded_audio`，不自动删片。
2. **字幕构建后、整片视频编码前**用`talking-batch --stage review`或`pre-render-review`生成与成片同采样切割、拼接和尾部补齐的真实PCM，检查连续声音与全部内部切口。先处理会改变选段或气口的已知问题，再确认当前输入的审核。只改字幕时复用同时间轴的预听；原片、PCM和实际MP4仍共用同一0.2元账本。
3. **最终MP4生成后**独立复核实际编码的声音及同revision全部内部切口；分别报告完整覆盖、原始异常和仍不确定项。两种成片音频检查每批最多6个切口，均带前后约3秒上下文；截取窗口两端不是实际切口。

```text
vp audio-review --workspace-root <workspace> --project-dir <同一项目根目录> --source <原片> --stage source --execute
vp audio-review --workspace-root <workspace> --project-dir <同一项目根目录> --source <原片> --media <final.mp4> --plan <同revision的edit-plan.json> --stage final --execute
```

已有原片与成片的独立实测可用`--stage both`一次执行。付费执行默认返回后台job，复用`job-watch`等终态；`--foreground`仅供维护验证。前置审核的命令与决定格式见[固定口播流水线](stable-talking-head.md#4-渲染前集中审核)。`deliver`仍负责本地技术QC和PCM同步；最终听审消费实际成片，不把已渲染文件重新编码，也不更改选段。

首次检查有疑点时，可用`--stage final --focus 64:77,85:99`扩大上下文独立复核（示例秒数必须换成本次成片时间）。每次最多两个窗口，同一视频累计最多八个：优先在前四个内解决初检疑点，其余最多四个用于实际修剪后的变化验证；每个不超过90秒，沿用同一费用账本，不自动无限重听。先覆盖当前初检的具体异常，不把复核位置全部用于已经基本通过的切口。扩大窗口只给窗口整体四项判定和异常events，窗口内真实切口时码作为上下文，避免几十个切口的逐项输出挤爆1536 token上限；它不冒充又一次逐切口全覆盖，覆盖率仍以独立全量报告为准。窗口边缘观察会标`window_edge_observation`，不能单凭抽样末尾听不全，就认定实际切口吞字。复核结果与初检分别保存，冲突保留待审。

已知声音或切口问题改动后，先用`vp render --workspace-root <workspace> --source <原片> --plan <新edit-plan.json> --out <work/audio-preview/review.wav> --audio-only`生成真实PCM时间轴，再将它作为`--media`做上述局部复核。它与MP4使用相同采样裁切、拼接和尾部补齐，不编码视频；不是模拟音频，也不替代最终MP4的连续及全部切口听审。复核目标之外的窗口首尾截断要对照实际时间轴，不能据此继续删词。

角色或局部混声疑点优先在渲染前使用`--stage source --source-focus 55.4:55.9,130.8:132.1`（秒数仅为格式示例，换成本次候选）。每次最多4个目标、每个目标最长12秒，程序加前后3秒原声和目标内3张真实嘴型帧；同视频累计最多12个源片复核请求，仍共用0.2元预算。优先在初次8个以内解决，余下最多4个仅用于具体证据冲突的精确目标复核，不重听无变化的判断。图像与声音都绑定源片哈希和时码；只对目标判断，旁边领读作为对照。局部候选使用其实际词段边界，不能自行扩大目标再以邻接正文的通过结论覆盖候选；程序已自动提供前后上下文。闭嘴帧或低电平不能单独判身份，声画结论矛盾时精确复核或保留待审。完整原片听审和局部回源报告分别保存，不能用几个短窗冒充全片覆盖。

## 费用与恢复

预算事实源固定为`<project>/qc/audio-review/budget.json`，所有阶段和revision共用，不能换输出目录或新建项目绕过预算。输入音频先转为16kHz单声道PCM短窗，Base64直传既有阿里云业务空间，不上传到其他服务。请求关闭思考，使用API的`response_format={"type":"json_object"}`约束JSON、temperature=0、最大输出1536 token，无联网搜索或语音生成。JSON模式保证语法，不取代检查ID和覆盖校验；老响应的有限本地恢复仍保留。

每次请求先保存费用预留，再提交网络调用；收到的结果先落盘再解析。相同音频内容、窗口和提示复用已完成结果。超时、网络错误、用量缺失、返回格式不完整时保留预留、报告incomplete，不自动重试付费请求；收到的JSON可以本地检查，不能丢弃账本重新请求。预算不足时保留已完成报告及未审项。

完整返回、费用已知，但逐切口JSON缺失ID时不能猜补。用户已要求继续核实，可显式运行`audio-review --stage final --recheck-invalid --execute`：最多两批失败切口，每批拆成至多两个三切口真实重听请求，保留原始坏回复、费用和父子请求谱系；未发送的后续批次接着完成，已完成批次复用。默认不触发付费补听，超时/截断/用量未知仍拒绝重提；子请求再失败就保留incomplete，不递归重试。全部费用仍计入同一0.2元预算。

已收到的完整JSON响应允许有实测依据的有限本地恢复：中文左引号前漏了ASCII起始引号；`evidence/ heard/ speaker_notes`文本字段把键值分隔写成未闭合键加中文冒号；或JSON语法虽合法，但一段已收到的`evidence`文本被吞进`evidence：<原文>},{`字段名且值为字面量`id`。最后一种只提取已返回的原文，必须已存在正确检查ID和四项判定；空证据、其他形式或缺项仍拒绝。恢复不补写判定、时码或证据；仍须通过完整JSON、全部检查ID和字段校验，原始响应不变，结果记录`local_parse_repairs`。其他损坏或截断继续保留incomplete，不另调模型“猜补”。

报告的`cost_from_usage_cny`按API实际返回的prompt/completion tokens和公开未缓存价格计算，缓存优惠未核实时按未命中价计，是用量折算费用，不等于账户账单核销。`budget_occupied_cny`还包括未知结果的预留。二者不能混为“实际已扣费”。

## 读报告与处理结果

从`qc/audio-review/latest.json`取得报告路径。每项给`pass / issue / uncertain`及声音依据，四项为：

- `prompt_residue`：另一声音或领读残留。
- `nonformal_speech`：试词、自我纠正、拍摄交流。
- `word_clipping`：音节或词头尾被剪断。
- `breath_cut`：呼吸被明显硬切。

原片里出现领读和拍摄交流是待选段信息，不代表成片有缺陷。成片的issue需回查对应音频及源片，再决定是否修剪；不确定项保留待审。模型时间位置为估计，精确切点以时间轴和波形为准。漏审、截断响应或用量不明不能作为全部通过。报告绑定源片/成片哈希及revision；修片后旧报告失效，但已花费用仍计入同一预算。

即使模型全部pass，仍仅称“音频模型复核通过”；`human_listening`保持`not_checked`，不能写成人工逐切口听审通过。整体交付是否可用继续按真实证据判断。

已观察到的误报：模型可能把窗口首尾未完整截入的词判为吞字，把“说难听点”“就就”等正常口语判为非正式发言，或把同一人语调变化判为另一声音。遇到这类结果先检查窗口边缘、实际切口位置与原片上下文；“不像书面朗读”不是删除依据。初检与扩大上下文结论冲突时保留两份报告及待审状态，不能只选更肯定的一份。

官方依据（2026-10-13核对）：[输入规范与音频换算](https://help.aliyun.com/zh/model-studio/qwen-omni)、[模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。当前北京价格输入0.8元/百万token、输出2.7元/百万token，音频7 token/秒；脚本预留采用更保守输入上界并计入最大输出。价格或模型改变时先更新计价与验证，不静默套用旧预算。

JSON模式支持情况见[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。带画面的源片复核已在本次原片真实完成，不需要额外视觉模型。
