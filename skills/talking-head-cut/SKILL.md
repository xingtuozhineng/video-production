# 真人口播剪辑

本 Skill 是 [video-production](../video-production/SKILL.md) 的口播子流程；主 Skill 完成环境门和类型判断后在当前任务进入这里。直接调用时，若当前任务没有环境报告，先执行主 Skill 的 `scripts/check_env.py --project-dir <workspace-root> --json --write-tools` 一次。主 Skill 统一管理百炼 Key、转写脚本及字体，口播子流程管理原声、接句、字幕语义和视听验收；不复制第二份配置。

输入最少为一个 raw 路径和一句风格定调。输出带字幕 MP4、剪映可编辑草稿（含完整素材）、SRT 和质检结果。口播的视频产出、预览/审片画面及可编辑工程画布统一竖屏（height > width）；原片和随草稿保留的完整源素材保持原样，文字/音频产物无横竖屏之分。提供短语分页、ASR 异常检查、波形同步检查；运行环境继承主 Skill 的唯一环境门。实际修改依据与验证边界见 [validation.md](references/validation.md)，需要判断能力是否经过实测时读取。

普通剪辑默认使用完整基础字幕＋少量重点，执行主 Skill 的 [固定口播流水线](../video-production/references/stable-talking-head.md) 的`talking-batch`五阶段入口。程序一次提供每阶段完整审核包并连续执行机械步骤，Agent集中修改角色/选段、气口、校字与异常分页，在review阶段完成渲染前审核后再deliver；长阶段后台运行并等待终态。按用户选定的500K上下文完成单片，片内不主动压缩；保留全部中间产物和已确认依据，不以丢失信息换成本。逐页精修、复杂滚动动效或额外音轨仅在用户要求时启用。

## 1. 接收素材并确定执行路线

- 完整流程交付 MP4＋剪映可编辑草稿，在 `production.json.export_format` 记录 `both`。开始完整视频路线时读取主 Skill 的 [剪映工程导出](../video-production/references/jianying-export.md)，按环境门报告确认导出依赖，保留源片切段及独立字幕、BGM 轨道；两项产物消费同一最终时间轴。

- 按主 Skill 的 [工作区规范](../video-production/references/workspace-layout.md) 使用 `projects/talking-head/<日期>-<项目名>/`；原片可保留在工作区根目录并保持只读，路径、大小、修改时间、媒体时长、帧率/时间基、旋转、分辨率、音轨及色彩信息写入输入清单。返工复用原项目和 revision，不新建 `-v2` 目录。
- 只给 raw＋风格时：保留独有论点、例子和顺序，删拍摄废片与确定的重说，保持原声和原速；目标时长随有效内容形成。用户明确要求时才做高光摘选、重排、整体变速或改写式制作。
- 把风格定调写成 `style.json`：语气、节奏、字幕层级、强调色、标题策略、人物构图、动画强度、音乐、输出规格。默认保留原片分辨率等级和帧率，输出统一竖屏；横转竖画布、旋转信息处理、规格覆盖与核验按主 Skill 的 [固定口播流水线](../video-production/references/stable-talking-head.md) 执行。其他缺省项按素材作可逆选择并简述，无需逐项询问。用户提供参考成片或字体样例时才读 [styles.md](references/styles.md)。
- 主 Skill 的环境门已给出本次可用路线、工具绝对路径和版本；直接消费 `check_env.py --project-dir <workspace-root> --json --write-tools` 的结果，使用工作区共享的 `video-production-deps/tools.json`，不再探测 PATH、递归搜索磁盘或检查其他项目缓存。模型选择只在已有路线未 ready 时处理，并记录实际采用的模型/路径。
- 开始时记录可用听审通道及接管方式。用户要求自动音频听审时，读取主Skill的 [Qwen-Omni音频复核](../video-production/references/audio-review.md)，在选段前检查原片、整片编码前预听同时间轴PCM、编码后复核实际MP4，共用单视频0.2元预算。模型复核与人工听审分别记录。只选择一个最终时间轴和渲染后端。
- 仅在渲染后端或依赖组合尚未有可复用证据时，先用 20–40 秒包含重说、接句和强调字幕的片段校准一次；已有同版本通过证据时直接进入全片。校准样片不是强制用户审批点。工具不可用时完成不依赖它的素材清单、风格和剪辑设计，明确缺失项；不把缺少依赖的任务说成剪辑完成。

完成条件：素材可读取、风格已具体化、输入/输出边界清楚、执行路线有当前可调用证据。

## 中间链路约束

- 环境检查、工具解析和安装只由主 Skill 完成一次；本 Skill 直接使用其结果和项目 `video-production-deps/` 中的 FFmpeg。
- 已确认的固定命令直接复用，参数不清楚时才查`contract`或`--help`；优先查看JSON/TSV摘要。只有帮助和产物不足以定位故障时，才按目标函数或行范围读取源码。
- 转写完成后生成一次可检索的 utterance/word 索引，内容选择、接缝、气口和字幕阶段都复用它；阶段之间传递文件，不反复重读完整转写。
- 需要查Word脚本、源／成片词范围、候选气口或最终接缝时，使用主 Skill 的 [输入查询](../video-production/references/input-inspection.md)；沿用当前母版／转写，不通过多个 dump、inspect、range-text 脚本重复包装数据。

## 2. 建立可追溯的原声文字稿

- 选段前必须读 [拍摄角色与发言用途](references/recording-roles.md)。依次判断谁在说、是否为正式正文、同一内容选哪一遍；出镜者的试词/拍摄交流也要排除。`index`生成的角色表须完成`content_review`，非正式片段用`spans.role=production`，用途未明用`unknown`；没有识别成词的声音用`excluded_audio`。`select --review`校验这些决定，不根据音量、低头或关键词自动删片。
- 默认读取主 Skill [asr.md](../video-production/references/asr.md)，共享 `.env` 已配置时用 `bailian_asr.py` 取得百炼词级时码与说话人标签。已有本次素材的可靠转写可复用；说话人信息不足时补齐所需证据。主角/画外提示的角色依据源片核对，不能固定认定 speaker 0 是主角；混合句的词级修正保留原模型标签与理由。字幕筛选不等于已经删除对应声音，媒体和字幕仍须消费同一保留词计划。
- 生成轻量预览代理与分析音频时保持原片时间对应，记录任何起始偏移、旋转处理和帧率转换；成片回源原片。VFR 使用实际时间戳，不用帧号÷平均 fps 假装精确时码。
- 做完整中文转写，取得词级时间戳；区分出镜讲述、场外提示、重拍和无效片段。说话人身份依据声音及上下文，脸部朝向只作辅助。
- 对专有名词、金额、否定词、同音字、弱起音、重拍交界逐处回查。ASR 校字仅修复识别，不改变讲话内容；字幕美化只动显示层。
- 此阶段读取 [editorial.md](references/editorial.md) 的 ASR 异常与接管规则，执行长词/重叠检查。提示＋重拍被合并时，按带上下文的短窗复识别并保留偏移及 ID 映射；高概率不能覆盖异常长时码。
- 在 `transcript.source.json` 保留稳定 word/utterance ID、原声文本、校正文本、source 起止时间和不确定项。ASR 有时间段无文本、重叠时间或无法解释的长空白时检查原声，而非自动当废片删除。

完成条件：整条素材被覆盖，候选有效话语有源时码，低可信区间被列出且不被默默删除。

## 3. 先选内容、标注气口，再执行剪辑

拿到词级字幕后、切音视频之前，必须读取 [semantic-pacing.md](references/semantic-pacing.md)，按其中五步执行。先缓存转写 → 选保留内容 → 导出全部气口候选并逐处填写类别/目标/理由 → 用主 Skill [正式脚本契约](../video-production/references/script-contracts.md) 的 `compile_timeline.py` 一次生成并校验时间轴与词映射 → 制作字幕、渲染和验收。`selection-plan.json`、`pause-decisions.json`、`edit-plan.json` 是可复用产物，不用对话临时推算切点。编译失败时修改内容选择或气口决定，不另写时间轴修补脚本。

- 按完整语义比较重拍，保留内容完整、音质可用、表达自然的一次；不以“最后一遍”或“最长一遍”作为唯一依据。保留有强调作用的重复、语气词、呼吸和表情收尾。
- 将删除分为重拍/口误、提示/准备、无效等待和用户要求的内容删减。每项记录源区间、理由和保留句；没有把握的独有内容先保留。
- 为每个相邻话语建立接缝记录：上一句实际收音、下一句弱起音、语义关系、原有总留白、拟删除区间、拟保留总留白、保护词和复核状态。未修改接缝也说明保留原因。
- 结合波形、频谱、VAD、转写和实际视听查找等待；固定音量阈值仅生成候选。字幕换屏、ASR 分段、低头或嘴型不能单独决定音频切点。
- 紧凑口播按语义设置总间隔：**句内20ms、同观点展开30ms、完整句60ms、话题切换120ms**，写入 `style.json` 的 `pause_targets_ms`；这是当前风格起点，显式要求和必要字音保护优先。使用 `scripts/semantic_pacing.py` 同时处理已有接句和句内候选，先标注再执行；不再使用全片统一50ms默认值。报告同口径的均值、中位数、分类型统计及例外。ASR空档不等于纯静音，本来更短的不补长，零时长/不确定词相邻气口保留待审。精确30ms音频和25fps画面的累计取整规则见上述参考；旧 `pause_plan.py` 仅保留用于明确要求帧网格统一目标的兼容任务。
- 保护弱辅音、词头、尾音及有意义的吸气。短淡化只解决接缝突变；若涉及音视频交叠或 J/L cut，显式记录其时间映射，不能把带声嘴型与另一句拼错。普通口播优先保持同期声硬切。
- 连续检查整段是否仍有“说一句—准备—重新说”的节奏，再局部检查每个切口吞字、爆音及表情/手势跳变。轻微裁切推近可减弱跳剪，但需保住脸、嘴、手势，不能用遮挡掩盖内容误删。
- 字幕制作前完成主 Skill [保留区间复核](../video-production/references/stable-talking-head.md#进入字幕前完成保留区间复核)：核对首尾词、局部混声、无词空隙和最终切口，解决会改变剪切范围的已知问题后锁定选段。角色/领读残留检查不留到首次全片渲染后的收尾阶段。气口决定用 `pause-author` 批量填写。

完成条件：所有取舍有依据；每个接缝可追溯；完成内容和节奏粗剪，尚未因字幕动画拖长讲话。

## 4. 固定时间轴，生成字幕和包装

时间映射、交付结构与质检细则见 [timeline-qc.md](references/timeline-qc.md)，在首次应用剪辑前读取。

- 用一份 `edit-plan.json` 记录 source 区间与 final 区间；`source.fps` 必须记录源视频真实帧率，`fps` 记录成片帧率；已有计划缺少 `source.fps` 时重新探测原片并停在计划阶段，不能复制成片 `fps` 作为替代。按实际应用结果生成新 revision。运行 `scripts/check_timeline.py --plan edit-plan.json` 后才进入渲染。音视频、字幕、标题和动画都消费该 revision。
- 默认 `caption-draft` 自动生成完整单/双行字幕，通读 `.review.tsv`，用少量 `caption-edits.json` 校字、标注关键结论/数字/行动和修正异常页，再 `caption-build --edits`。转写校正和断行属于常规制作，按实际问题集中处理，不为减少调用而略过。普通页保持全白，无需逐页填写 takeaway、重复整份JSON或追求每页强调。重点来自本句语义，不用全局名词表匹配；普通重点优先白色粗体。用户要求逐页精修时才按 [editorial.md](references/editorial.md) 写完整语义设计。
- 结合主题、列表、对比与结论设计顶部层及单/双行层级，逐项按原声进入。人物曝光、白平衡、肤色按实际需要温和修正并对照，不把原片直出自动当作视觉完成。
- 根据实际人物构图设置字幕框及平台安全区域，检查字体真实加载、字符覆盖和可见字高。常驻标题只有风格需要时才添加；标题从素材论点提炼，避免增加原声没有的承诺。
- 字体选择读取主 Skill 的 [fonts.md](../video-production/references/fonts.md)，按正文、短重点和风格选择内置黑体、宋体、文楷或 Google Fonts 文件并等待实际加载；装饰字体优先短重点，不替换整片长字幕。依照真实字体重新检查大小/宽度，不能依赖操作系统字体名碰运气。
- 动画使用固定帧时钟，随重音落点出现，在对应字幕区间内收完；口播时长优先于动画时长。
- 需要两行滚动字幕、调整字幕/重点存在时间或用户提供字体截图时，读 [rolling-subtitles.md](references/rolling-subtitles.md)。紧凑口播采用语义短语行：讲到下一行时，旧行上移、新行在下方出现；重点在对应词开始时出现并随行退出。使用 rolling_captions.py 与 RollingCaptionLayer，不按固定20字拆句；正文和重点可分别指定字体。
- 音乐不能抢占口播。保护人物的关键结论、表情和收尾。
- 后续任何剪辑变动均重建映射及字幕，再渲染受影响片段；不在旧 SRT 上凭感觉平移多处时间。

- 最终字幕构建后执行主 Skill [渲染前集中审核](../video-production/references/stable-talking-head.md#4-渲染前集中审核)。集中核对字幕、领读/非正式发言、吞字和换气；先应用已知修改，再确认当前输入。`render/deliver`检查同一审核门，缺失或过期时停在编码前；字幕独立修改复用同时间轴音频预听。

完成条件：工程、字幕、动画均引用同一时间轴版本；当前输入前置审核已完成；实际渲染帧验证单行、双行、长句、数字/英文及强调字。最终成片解码、同步和视听验收仍按下一阶段执行。

## 5. 验收并交付

- 执行内容、连续表达、逐切口音画、字幕、构图和文件检查；校准与全片均增加 PCM→最终编码音频波形延迟比对，具体命令见 [editorial.md](references/editorial.md)。修复固定偏移后重测，不能照抄历史 42.7ms。渲染命令成功只证明产生文件。
- 按剪映导出流程执行 `export_jianying.py`，使用与成片同 revision 的 `edit-plan.json`、字幕及实际使用的附加轨道。交付 `final.mp4`、完整 `剪映工程/`、`final.srt`、原渲染工程及依赖锁文件、`style.json`、`edit-plan.json`、`qc.json`，执行主 Skill 的双产物检查并记录路径。SRT 是文字/时间交换版；剪映基础文字可编辑，未转换的字体和动画差异写入报告。
- `qc.json` 每项使用 `pass / fail / not_checked`，记录实际方法、区间和证据。若当前环境不能听审，继续交付可审片版本及待审切口，不以 ASR/静帧冒充自然度通过；存在必检 `fail` 或 `not_checked` 时标为 `review_required`。
- 成功答复给出 MP4 与剪映草稿目录位置，简述源片显示分辨率/帧率、实际成片规格、时长、主要取舍和验收边界。制作可发布文件不等于向平台发布；仅在用户明确授权发布时进入平台动作。

## 参考成对学习

用户另给 raw/成片时，先核实对应关系，再对齐两者转写和关键视听片段，建立原句→人剪保留句、删减原因、接缝和字幕层级的小样本表。共同布景或时长不能证明对应关系，稀疏抽帧不能量出剪辑点或动画曲线。可继承有证据的风格，不能从两条样片声称学会所有人剪判断。
