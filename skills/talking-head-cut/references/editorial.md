# 逐句编辑与实测问题修复

## 字幕重点的决策顺序

默认完整基础字幕＋少量重点：锁定有效原声后，使用程序分页，通读简洁的字幕审核表，只校正错字/异常断行，并挑选少量关键判断、数字与行动作强调。普通页全白，无需逐页写 takeaway。用户明确要求逐页精修时，才为每句写“观众应记住什么”（takeaway）及布局。关键词表仅可定位候选，不能批量决定强调结果。

| 原声表达 | 语义重点 | 表达方式示例 |
|---|---|---|
| 你千万不要去碰 FDE 的业务 | “千万不要”与所限制的行为 | 判断大白粗字，业务作解释层，保留否定关系；不只给 FDE 上色 |
| 一个月赚个三五十万 | 数字范围与时间单位 | 完整金额短语加粗，月份/动作作铺垫；改写成阿拉伯数字前确认原声含义 |
| 学思维、学模式、掌握渠道、掌握销售能力 | 并列行动与递进顺序 | 按口播逐项进入的编号清单，编号可用主题色；未说内容不提前铺满 |

这些是独立验证中的案例，不是跨视频使用的固定关键词或标题。颜色分工：正文细白；普通语义重点先用白色粗体、字号或下划线；主题色用于标题、列表编号、类别关系等结构。用户明确指定“重点都用某色”时遵循用户选择。每页强调记录 reason，role 为 focus 或 structure；声学重读未经听审时写“语义强调，词时码定位”，不冒充检测到了重音。

基础字幕保持稳定的单/双行模板，按开始/中间/结尾和异常页实帧核对字高、遮脸和安全区。逐页精修时可另选顶部主题、铺垫＋结论、数字、对比或编号清单布局；字幕以阅读为先。

人物处理先检查曝光、白平衡和肤色；有需要才温和修正并保存前后对比，保留皮肤质感和人物身份。参考片更柔和不等于已识别其滤镜。

## 可执行短语分页

`scripts/caption_pages.py` 接收 final 词时码和 Agent 编写的逐页计划，输出字幕 JSON＋SRT。它执行和检查已经做出的语义决策，不自动理解全文、不用固定字数切卡。输入可沿用独立验证 `words.final.json` 的字段：revision、words[].id/instance_id/corrected_text/final_start_s/final_end_s。

计划示例（word keys 必须换成当前素材实际的 `instance_id:id`）：

```json
{
  "revision": "cut-001", "fps": {"num":25,"den":1}, "duration_frames":250,
  "protected_phrases":["三五十万","全栈工程师","完整SOP"],
  "pages":[{
    "takeaway":"不要承接该类业务", "layout":"setup-conclusion",
    "lines":[["k1:w1","k1:w2"],["k1:w3","k1:w4"]],
    "emphasis":[{"word_keys":["k1:w1","k1:w2"],"role":"focus","reason":"否定判断决定整句意思"}]
  }]
}
```

脚本要求保留词按 final 顺序恰好覆盖一次、重点是页内连续词、分页不拆保护短语；短于 0.4 秒的卡片列为待改候选。短语表由当前句意生成，允许用户直接改。原声本来只有一个短重拍词时，可说明为何保留短卡，而不是删音或补静音凑长度。排版、渲染组件应消费这些逐页决策，禁止重新用全局关键词表覆盖。

## ASR 合并提示与重拍

声道/疑词核对、短窗复识别和校字是随原声及转写质量变化的常规工作；断行修正还受自动分页与字体宽度影响，不能仅凭改了多少页认定为浪费。影响角色、词范围或切点的疑点先在选段阶段处理；仅影响显示文字的校正集中用于字幕构建。渲染后重复这些已可完成的内容检查而引发全链路重做，才是应优先避免的流程返工。

运行 `scripts/speech_checks.py asr --transcript transcript.source.json --out asr-anomalies.json`。按原字数/时间检查长词、倒序/重叠、异常概率；高置信单字跨数秒照样触发候选。阈值是定位工具，不是正确性判据。

遇到候选，带左右上下文做两个互有重叠的短窗口复识别，用波形/VAD与全文语义核对提示和正式讲述。保持源时间偏移，赋新稳定 ID 并保留旧 ID→新 ID 关系；去重依据同一源时间段，不能误删本来存在的重复。最多两轮仍不确定则保留争议原声、列入听审，不不断拆小到失去上下文。口误选择或重拍选择不得夹短 ASR 词包络以凑切口。

已删除的 ASR 词包络若碰到保留边缘，即使只有 20–30ms，也单列接缝待听，不能因“误差很小”推定无提示残音。

## 编码后音频同步

固定流水线的 `deliver` 自动运行 `sync-check`，按同一时间轴重建开中末的短PCM窗口，和最终MP4的相同窗口做波形比对；报告位于交付目录的 `sync/sync.json`，无需临时 sync_check.py。单独复查用 `vp sync-check --workspace-root <workspace> --plan <plan> --media <final.mp4> --out-dir <qc/sync>`。已有完整同时间轴PCM时仍可用 `speech_checks.py sync`；它需要 NumPy。

检测窗口应包含开头、中间、结尾和改动接缝两边的有声区，避开静音。输出正 lag 表示编码音频滞后，低相关/边界峰或无声写 not_checked。20ms 是脚本默认工程容差，可按帧率与需求明确调整，不能当成人类可感知阈值。

发现固定偏移时定位 PCM、编码、封装中的起因，修后重测。独立验证中约 +42.7ms 通过同时间轴 PCM 重新封装修复；这不是其他视频应固定减去的数字。非线性/累计漂移应回查采样率和剪辑映射。波形同步不证明逐字字幕准确或接句自然。

## 听审接管

用户要求自动听审时走 [Qwen-Omni音频复核](../../video-production/references/audio-review.md)：原片在选段前检查，成片在deliver后连续检查并覆盖全部内部切口，单视频原片/成片/复核累计预算0.2元。Agent只读程序汇总与异常，不临时写API调用脚本或逐切口轮询。模型反馈写`audio_model`，人工听审状态独立，音量或波形相关性不能代替听辨。

任务开始记录实际听审通道。若无法听审，输出全片和可点击的每个切口、疑词、边缘相交词以及对应源片时码。`qc.json` 保留 not_checked；用户可逐项回填听审结论。状态由当前证据计算，不因“工程能重建”“全部字幕存在”自动变成 passed。
